# Configs

Every run is driven by a YAML config. The `model:` block's `model_name` field selects
the model class (see `parser/helper/util.py:get_model`); the rest of the schema is
documented in the top-level `README.md`. Configs use **relative `data/` paths** and no
hard-coded W&B entity, so the only thing you must provide locally is `data/`.

## Layout

| Path | Contents |
|------|----------|
| `config/baselines/` | Upstream / reference baselines on PTB: `tnpcfg`, `npcfg`, `nlpcfg`, `nblpcfg`, `cpcfg`, `fast_tnpcfg`, and the SimplePCFG drops `simple_npcfg_*` / `simple_cpcfg_*`. `NLPCFG` / `NBLPCFG` require the separate head-annotated `data/ptb-*-lpcfg.pickle` files. |
| `config/formal/` | Formal-language Hol-PCFG: math (`symmath_infix`) and `kaomoji`. `_main` = NT 4096, `_nt1024` = NT 1024. |
| `config/multilingual/` | Per-language constituency-induction configs. `{hnpcfg,snpcfg,scpcfg,npcfg}_<language>.yaml` for the 6 SPMRL languages (basque/hebrew/hungarian/korean/polish/swedish) + japanese; plus Hol-PCFG-only `hnpcfg_{english,german,french,chinese}.yaml`, the char-level `hnpcfg_japanese_char.yaml`, and baseline-derived KTB configs `npcfg_japanese_nt30_t60_curriculum0.yaml`, `cpcfg_japanese_nt30_t60_curriculum1.yaml`, `tnpcfg_japanese_r500_nt250_t500_curriculum0.yaml`. All Hol-PCFG configs share one p3 hyperparameter set (NT=4096, T=8192, s_dim=512, fixed tau_*_init; the non-SPMRL ones additionally carry the W&B tag p3-eji18kkl); `scripts/launch_multilingual_pcfg.py` drives the SPMRL subset via constructed paths. |
| `config/seminfo/` | Canonical SemInfo (Chen et al., ICLR 2025) config `hnpcfg_nt1024_t2048_rank1_seminfo.yaml`. **Different YAML schema** than the native families — parsed by `parsing_by_maxseminfo/utils/myargparse.py`, not `train.py` / `get_model` — and run via `python -m parsing_by_maxseminfo.train` (see the top-level README "Experiment families"). |
| `config/sweeps/` | `{hn,sn}_pcfg_nt_sdim_base.yaml` (native NT × s_dim sweep) and `{hn,sn}_pcfg_seminfo_nt_sdim_base.yaml` (SemInfo NT × s_dim sweep) — hand-maintained templates. |

Frozen / one-off configs (norm-mode ablations, HC-PCFG variants, Optuna outputs, English
v2hp scale variants, Japanese variants) live under `archive/configs/` — see `archive/README.md`.

## Generated configs

`config/sweeps/nt_sdim/` is **generated** by `scripts/launch_nt_sdim_sweep.py` from the two
`*_base.yaml` templates (NT/T/s_dim overridden per combination) and is **gitignored**. It
is recreated on demand — do not commit it. Likewise `config/sweeps/seminfo_nt_sdim/` is
generated by `scripts/seminfo/launch_seminfo_nt_sdim_sweep.py` from the
`*_pcfg_seminfo_nt_sdim_base.yaml` templates and is gitignored.

## Data format

Most configs reference `data/clean/<lang>-{train,val,test}.pickle` — the
`word`/`pos`/`gold_tree` format produced by `preprocessing.py` and read by
`parser/helper/data_module.py`. The exceptions are the lexicalized `NLPCFG` /
`NBLPCFG` baselines, which reference `data/ptb-{train,val,test}-lpcfg.pickle`
because they need head-annotated lexicalized data. The legacy `.pkl` dumps (old
upstream `source`/`idx2word` indexed format) are not used by any living config
or script (the C0 analysis script `scripts/c0_phase_landscape/build_symbol_labels.py`
also reads `.pickle` now) and can be removed.
